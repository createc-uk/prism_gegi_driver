# Rebuilding the `ros-melodic` WSL2 distro after a machine reset

A reset wipes the WSL2 distro (`ros-melodic`) and its catkin workspace
(`~/gegi_ws`). The Windows repo is the single source of truth and is untouched —
this restores the Linux side from it.

There are two halves: **Windows setup you must do by hand** (needs admin + a
reboot, and possibly a BIOS change), then a **one-shot provisioning script**.

---

## 0. Pre-flight: what the reset removed

```powershell
wsl --status          # may report virtualisation not enabled
wsl --list --verbose  # "no installed distributions"
```

If `wsl --status` says *"virtualisation is not enabled"* you must do step 1.
If it only says *"no installed distributions"*, skip to step 2.

---

## 1. Re-enable the WSL2 Windows features (admin + reboot; NO BIOS)

Firmware virtualization does **not** need touching if a hypervisor is already
running — check with:

```powershell
systeminfo | Select-String "Hyper-V|Virtualization-based"
```

"A hypervisor has been detected" / "Virtualization-based security: Running" means
VT-x/SVM is already on in firmware; the WSL failure is only the missing Windows
*features*. (On this machine that was the case.)

In an **elevated** PowerShell ("Run as administrator"), enable WSL2 and install the
kernel in one shot — this turns on both required features, no BIOS:

```powershell
wsl --install --no-distribution
```

Then **reboot**, and confirm:

```powershell
wsl --set-default-version 2
wsl --status
```

> If `wsl --install` is unavailable on an older build, enable the features directly:
> ```powershell
> dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
> dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
> wsl --update
> ```
> then reboot.

`wsl --status` must no longer complain about virtualization before continuing.

---

## 2. Reinstall an Ubuntu 18.04 rootfs named `ros-melodic`

ROS Melodic needs Ubuntu 18.04 (Bionic). The repo and scripts expect the distro
to be named **`ros-melodic`**, so import a rootfs under that name.

```powershell
# Fetch the Ubuntu 18.04 WSL rootfs (~304 MB)
mkdir C:\wsl -Force
curl.exe -L -o C:\wsl\bionic.tar.gz `
    https://cloud-images.ubuntu.com/releases/bionic/release/ubuntu-18.04-server-cloudimg-amd64-wsl.rootfs.tar.gz

# Import it as a distro literally named "ros-melodic"
wsl --import ros-melodic C:\wsl\ros-melodic C:\wsl\bionic.tar.gz --version 2

# Enter it
wsl -d ros-melodic
```

> If that image URL is unavailable, install **"Ubuntu 18.04.6 LTS"** from the
> Microsoft Store, open it once to create the user, then from PowerShell:
> ```powershell
> wsl --export Ubuntu-18.04 C:\wsl\bionic.tar
> wsl --import ros-melodic C:\wsl\ros-melodic C:\wsl\bionic.tar --version 2
> wsl --unregister Ubuntu-18.04
> ```

Optional — create a non-root user (the rootfs logs in as root by default); the
provisioning script works fine as root too.

---

## 3. Provision ROS + build + regenerate the helper scripts

Inside the `ros-melodic` distro, run the provisioning script straight off the
Windows mount. It installs ROS Melodic, the app dependencies, builds the
workspace, and **recreates the `sync.sh` / `build.sh` / `run.sh` helpers** that
were lost (they live in `~/gegi_ws`, outside the repo, by design).

```bash
bash /mnt/c/Users/Aliyu.Bala/Documents/GeGI_Driver/ros_phds_gegi_driver/setup/wsl/provision_ros_melodic.sh
```

Override the repo path if yours differs:

```bash
WIN_REPO=/mnt/c/path/to/ros_phds_gegi_driver \
    bash /mnt/c/.../setup/wsl/provision_ros_melodic.sh
```

---

## 4. Verify (no detector, no roscore needed)

```bash
# fresh shell so ~/.bashrc sources ROS + the workspace
cd ~/gegi_ws
bash src/phds_gegi_driver/test/run_tests.sh    # pure-logic suite
```

Then the normal loop from the README works again:

```bash
cd ~/gegi_ws && ./sync.sh && ./run.sh     # after Python edits
cd ~/gegi_ws && ./build.sh && ./run.sh    # after C++ edits
```

---

## Notes

- The helpers are regenerated by the provisioning script, not committed, matching
  the original "live outside the repo" design (see the main README).
- Calibration in `config/isotopes.yaml` is detector-specific — a rebuild does not
  change it, but if the *detector or rig* changed, read `docs/PORTING.md` §1.
